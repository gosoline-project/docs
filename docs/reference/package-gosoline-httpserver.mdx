# Gosoline SDK HTTP server package

The Gosoline SDK's `pkg/httpserver` package integrates an HTTP server with the application kernel. Import it as `github.com/justtrackio/gosoline/pkg/httpserver`; `httpserver.New(name, definer)` returns a kernel module factory and reads server configuration from `httpserver.<name>`. The SDK installs its request-metric middleware and server metric recorder as part of constructing the server.

This is distinct from the published `github.com/gosoline-project/httpserver` module documented in the [published HTTP server reference](/reference/package-httpserver). The modules are separate implementations, though they currently author the same eight canonical metric names and dimensions.

## Metrics

The SDK installs its metric middleware and recorder by default. After a matched route's middleware chain unwinds, it emits four high-priority monotonic `Count` counters: the statusless `http.server.requests` (`name`) and `http.server.routed.requests` (`name`, `route`, `request.method`), plus `http.server.responses` (`name`, full `response.status_code`, bounded `response.status_class`) and `http.server.routed.responses` (those status dimensions plus `route` and `request.method`). All four count matched requests, including those aborted by authentication, concurrency, or chaos middleware; unmatched paths emit none. Only the existing request counters receive zero-valued defaults: one per configured server and per registered application route/method pair. The new response counters have no zero defaults. Matched `/health` requests are counted, but its separately registered route has no pre-request zero default. The duration histogram retains the full status code without a class, and the rejection counter remains statusless; neither definition changes. See [Metric schema](/reference/metric-schema) for the V1→V2 history and writer-specific selectors.

| Metric | Instrument | Authored unit | Dimensions | Description |
|---|---|---|---|---|
| `http.server.requests` | monotonic counter (high priority) | Count | `name` — configured server name | One count for each matched request, including requests aborted after route matching. Unmatched requests are excluded. Configured servers receive a zero-valued default. |
| `http.server.routed.requests` | monotonic counter (high priority) | Count | `name` — configured server name; `route` — normalized Gin route template; `request.method` — HTTP method | One count for each matched route, including `/health` and requests aborted after route matching. Unmatched requests are excluded. Registered application route/method pairs receive zero-valued defaults; the separately registered `/health` route has no pre-request zero default. |
| `http.server.responses` | monotonic counter (high priority) | Count | `name` — configured server name; `response.status_code` — decimal numeric status; `response.status_class` — `1xx` through `5xx` (default outside 100–599) | One per matched response after the middleware chain unwinds, including responses from aborted requests and matched `/health`. Unmatched routes are excluded. No zero-valued defaults. |
| `http.server.routed.responses` | monotonic counter (high priority) | Count | `name` — configured server name; `route` — normalized Gin route template; `request.method` — HTTP method; `response.status_code` — decimal numeric status; `response.status_class` — `1xx` through `5xx` (default outside 100–599) | One per matched response after the middleware chain unwinds, including responses from aborted requests and matched `/health`. Unmatched routes are excluded. No zero-valued defaults. |
| `http.server.request.duration` | histogram | ms | `name` — configured server name; `route` — normalized Gin route template; `request.method` — HTTP method; `response.status_code` — decimal response status | Duration of a matched HTTP request. The histogram retains the full response code but does not carry `response.status_class`; keep it for latency distributions. |
| `http.server.rejected.requests` | counter | count | `name` — configured server name; `route` — normalized Gin route template; `request.method` — HTTP method | Requests explicitly rejected by the concurrency middleware. Ordinary 4xx/5xx responses are not necessarily rejections; this metric has no response-status dimension. Registered routes continue to receive zero-valued defaults. The existing rejection definition is unchanged by the response-counter restoration. |
| `http.server.active_request.count` | gauge | count | `name` — configured server name | Current number of requests tracked as active for the named server. Updated on request start/completion and sampled at startup, every 10 seconds, and during shutdown. |
| `http.server.connection.count` | gauge | count | `name` — configured server name | Current number of tracked open connections for the named server. Updated on connection state changes and sampled at startup, every 10 seconds, and during shutdown. |

The SDK installs the metric middleware by default; exporting the observations still requires the application metric daemon. Wire `application.WithMetrics`, set `metric.enabled: true`, and configure at least one writer under `metric.writers`. The table shows canonical Gosoline names and authored units; see [Metric schema](/reference/metric-schema) for writer-specific names and duration conversion.

If this SDK server and the published HTTP server both write to the same backend with identical dimension values, the metrics do not carry a source-module dimension that separates the implementations. This SDK metric reference follows Gosoline `v0.68.4-0.20261021101322-e1a14ac09eab`; see the [pinned SDK middleware source](https://github.com/justtrackio/gosoline/blob/e1a14ac09eab0404cf620e1f3ee8a0fd5db259c0/pkg/httpserver/middleware_metric.go).
