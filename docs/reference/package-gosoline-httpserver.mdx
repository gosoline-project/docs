# Gosoline SDK HTTP server package

The Gosoline SDK's `pkg/httpserver` package integrates an HTTP server with the application kernel. Import it as `github.com/justtrackio/gosoline/pkg/httpserver`; `httpserver.New(name, definer)` returns a kernel module factory and reads server configuration from `httpserver.<name>`. The SDK installs its request-metric middleware and server metric recorder as part of constructing the server.

This is distinct from the published `github.com/gosoline-project/httpserver` module documented in the [published HTTP server reference](/reference/package-httpserver). The modules are separate implementations, though they currently author the same six canonical metric names and dimensions.

## Metrics

The SDK installs its metric middleware and recorder by default. After a matched route's middleware chain unwinds, it emits two high-priority monotonic `Count` counters: `http.server.requests` (`name` only) and `http.server.routed.requests` (`name`, `route`, `request.method`). Both count matched requests aborted by authentication, concurrency, or chaos middleware; unmatched paths emit neither counter. Each configured server and registered application route/method pair receives a zero-valued default for its counter. Matched `/health` requests are counted, but the separately registered health route has no pre-request zero default. The V2 duration histogram retains `response.status_code`, and the rejection counter records explicit concurrency-middleware rejections, not every 4xx/5xx response; those V2 definitions are unchanged by this request-counter follow-up. See [Metric schema](/reference/metric-schema) for their V1→V2 history.

| Metric | Instrument | Authored unit | Dimensions | Description |
|---|---|---|---|---|
| `http.server.requests` | monotonic counter (high priority) | Count | `name` — configured server name | One count for each matched request, including requests aborted after route matching. Unmatched requests are excluded. Configured servers receive a zero-valued default. |
| `http.server.routed.requests` | monotonic counter (high priority) | Count | `name` — configured server name; `route` — normalized Gin route template; `request.method` — HTTP method | One count for each matched route, including `/health` and requests aborted after route matching. Unmatched requests are excluded. Registered application route/method pairs receive zero-valued defaults; the separately registered `/health` route has no pre-request zero default. |
| `http.server.request.duration` | histogram | ms | `name` — configured server name; `route` — normalized Gin route template; `request.method` — HTTP method; `response.status_code` — decimal response status | Duration of a matched HTTP request. The route, method, and response status distinguish observations; this V2 histogram definition is unchanged by the request-counter follow-up. |
| `http.server.rejected.requests` | counter | count | `name` — configured server name; `route` — normalized Gin route template; `request.method` — HTTP method | Requests explicitly rejected by the concurrency middleware. Ordinary 4xx/5xx responses are not necessarily rejections; this metric has no response-status dimension. Registered routes continue to receive zero-valued defaults. This V2 definition is unchanged by the request-counter follow-up. |
| `http.server.active_request.count` | gauge | count | `name` — configured server name | Current number of requests tracked as active for the named server. Updated on request start/completion and sampled at startup, every 10 seconds, and during shutdown. |
| `http.server.connection.count` | gauge | count | `name` — configured server name | Current number of tracked open connections for the named server. Updated on connection state changes and sampled at startup, every 10 seconds, and during shutdown. |

The SDK installs the metric middleware by default; exporting the observations still requires the application metric daemon. Wire `application.WithMetrics`, set `metric.enabled: true`, and configure at least one writer under `metric.writers`. The table shows canonical Gosoline names and authored units; see [Metric schema](/reference/metric-schema) for writer-specific names and duration conversion.

If this SDK server and the published HTTP server both write to the same backend with identical dimension values, the metrics do not carry a source-module dimension that separates the implementations. This SDK metric reference follows Gosoline `v0.68.4-0.20261019134325-8cdd08040fb4`; see the [pinned SDK middleware source](https://github.com/justtrackio/gosoline/blob/8cdd08040fb45a36858b1f4906b1764a2b8b3b84/pkg/httpserver/middleware_metric.go).
