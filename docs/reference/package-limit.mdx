# limit package

The `pkg/limit` package provides rate limiters for operations that must wait until a limit permits them to proceed. The common `Limiter` interface exposes `Wait(ctx, prefix) error`; a fixed-window limiter can delay a caller after capacity is reached.

## API and activation

The metric middleware is opt-in. Attach a `limit.NewMetricMiddleware()` instance through a middleware-capable limiter's `WithMiddleware` method, using a `MiddlewareFactory` that returns it. The middleware counts each start at `OnTake`, terminal results at `OnRelease`/`OnError`, and throttles at `OnThrottle`.

## Metrics

The table lists canonical Gosoline-authored names and units. The metric writer renders them per backend: OpenTelemetry prefixes namespaced metrics with `gosoline.` and OpenTelemetry/Prometheus scale authored millisecond durations to seconds. See the [metric schema](/reference/metric-schema) for backend rendering and the complete contract.

| Metric | Instrument | Authored unit | Dimensions | Description |
|---|---|---|---|---|
| `limit.attempted.takes` | Counter | `count` | `name`: limiter name; `prefix`: wait prefix | Counts take starts at `OnTake`; no zero-valued defaults. |
| `limit.takes` | Counter | `count` | `name`: limiter name; `prefix`: wait prefix; `outcome`: `allowed` or `error`; `error.type`: `{{default}}` for allowed, `rate_limit_error` for error | Counts only mutually exclusive terminal outcomes at `OnRelease` or `OnError`; no zero-valued defaults. |
| `limit.throttled.takes` | Counter | `count` | `name`: limiter name; `prefix`: wait prefix | Counts throttles at `OnThrottle`; no zero-valued defaults. |

`outcome` and `error.type` carry the terminal callback result; there are no `pass`, `reject`, or `wait` values, and `outcome="throttled"` is not emitted. In the fixed-window limiter, reaching capacity increments `limit.throttled.takes` while the call waits; a successful wait then increments `limit.takes{outcome="allowed"}`, while cancellation during that wait increments `limit.takes{outcome="error"}`. These are separate event boundaries: do not sum `limit.attempted.takes`, `limit.takes`, and `limit.throttled.takes` as one outcome total. `error.type=rate_limit_error` is the middleware's generic operation-failure label, not a Go error type.

The `prefix` value is passed to the fixed-window limiter through `Wait`; the leaky-bucket limiter instead reports the literal `take` prefix. The middleware does not seed zero-valued defaults, so these counts come from outcome callbacks.
