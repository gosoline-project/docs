# ddb package

`pkg/ddb` provides a DynamoDB repository interface for model persistence. Gosoline's `mdlsub.NewOutputDdb` wraps its repository with `ddb.NewMetricRepository`; the wrapper instruments `PutItem`, while delete operations use `DeleteItem` and do not pass through this metric hook.

## API and activation

`ddb.NewMetricRepository(config, logger, repo)` creates the metric-wrapped repository. In the standard DDB model output, both `Create` and `Update` persistence route through `PutItem` and are recorded with `operation.name=save`; deletes are not recorded by this wrapper. See [`NewMetricRepository`](https://github.com/justtrackio/gosoline/blob/d2be354ca7bc975f6e7a33c6d2cbdec1330feb7d/pkg/ddb/metric_repo.go) and the [model output wiring](https://github.com/justtrackio/gosoline/blob/d2be354ca7bc975f6e7a33c6d2cbdec1330feb7d/pkg/mdlsub/output_ddb.go).

## Metrics

The table lists names and units authored by Gosoline. The OpenTelemetry writer exports names with a `gosoline.` prefix and converts authored `ms` durations to the OpenTelemetry duration unit. See the [metric schema reference](/reference/metric-schema) for the writer contract and `{{default}}` dimension behavior.

| Metric | Instrument | Authored unit | Dimensions | Description |
|--------|------------|---------------|------------|-------------|
| `ddb.operation.duration` | Histogram | `ms` | `operation.name`: `save`; `model.id`: repository model ID; `error.type`: `{{default}}` on success, `operation_failed` on error | Records one elapsed duration observation after each wrapped `PutItem` result, including errors, using the database-duration histogram profile. |
| `ddb.operations` | Counter | `count` | `operation.name`: `save`; `model.id`: repository model ID; `error.type`: `{{default}}` on success, `operation_failed` on error | Adds one after each wrapped `PutItem`/save result, including failures. |
Both metrics are High priority, so successful duration samples can now be admitted by CloudWatch where the former Low-priority success seed could suppress them. This may increase CloudWatch metric volume and cost; it does not change the actual operation priorities.
