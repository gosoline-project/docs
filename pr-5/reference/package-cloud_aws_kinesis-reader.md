# Kinesis shard reader

`ShardReader` is the per-shard worker in `github.com/justtrackio/gosoline/pkg/cloud/aws/kinesis`. It polls a Kinesis shard with `GetRecords`, passes record payloads to a `RecordHandler`, and advances the shard checkpoint. It runs until the shard is finished or its context is canceled.

In normal application use, `NewKinsumer(ctx, config, logger, settings)` owns shard assignment and creates readers for its assigned shards; call `Kinsumer.Run` with a `RecordHandler` to activate consumption. Configure the reader through the package's `Settings` passed to `NewKinsumer`, including `MaxBatchSize`, `WaitTime`, `ConsumeDelay`, and `ProcessingMode`. See [Kinsumer](/docs/pr-5/reference/package-kinsumer/.md) for the active public API.

## Metrics[​](#metrics "Direct link to Metrics")

Names below are Gosoline-authored canonical names. The OTEL writer exports them with a `gosoline.` prefix and converts millisecond-authored durations to seconds; `acquire.duration` is authored in seconds already. Units below are the emitter's authored units. See the [metric schema](/docs/pr-5/reference/metric-schema/.md) for writer conversion details.

| Metric                                | Instrument | Authored unit | Dimensions                                                                                                                      | Description                                                                                                                                                                                                                                                                                        |
| ------------------------------------- | ---------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cloud.aws.kinesis.consumed.messages` | Counter    | count         | `stream.name` (full stream name), `partition.id` (Kinesis shard ID), `error.type={{default}}` or `error.type=processing_failed` | Records in a completed GetRecords batch, including handler failures. `{{default}}` is the batch total; `processing_failed` counts failed records as an overlapping per-record subset.                                                                                                              |
| `cloud.aws.kinesis.process.duration`  | Histogram  | ms            | `stream.name` (full stream name), `partition.id` (Kinesis shard ID)                                                             | Elapsed `processRecords` work for one fetched batch, including handler execution, configured per-record `ConsumeDelay`, and checkpoint advancement; excludes the `GetRecords` request and the next-poll wait. If processing/checkpointing returns an operation error, this observation is omitted. |
| `cloud.aws.kinesis.reads`             | Counter    | count         | `stream.name` (full stream name), `partition.id` (Kinesis shard ID)                                                             | One successful `GetRecords` response. This counts read requests, not records; failed requests do not increment it.                                                                                                                                                                                 |
| `cloud.aws.kinesis.lag`               | Histogram  | ms            | `stream.name` (full stream name), `partition.id` (Kinesis shard ID)                                                             | AWS `GetRecordsOutput.MillisBehindLatest` for this shard, not wall-clock age of the last processed record. The reader reports the value on each successful response, begins with zero, and re-emits the latest value every 15 seconds while the shard reader runs.                                 |

Values accumulate across retries; successful acquisition adds no final observation.                                                             |
| `cloud.aws.kinesis.sleep.duration`    | Histogram  | ms            | `stream.name` (full stream name), `partition.id` (Kinesis shard ID)                                                             | Remaining per-record `ConsumeDelay` after subtracting the record's age. An observation is written only when that delay timer completes; a canceled wait emits none.                                                                                                                                |
| `cloud.aws.kinesis.wait.duration`     | Histogram  | ms            | `stream.name` (full stream name), `partition.id` (Kinesis shard ID)                                                             | Computed delay scheduled before the next poll: normally `max(0, WaitTime - elapsed since the preceding GetRecords call began)`, or zero when AWS-reported lag exceeds `WaitTime + ConsumeDelay`. This is the scheduled value, not elapsed time actually spent waiting.                             |

### Measurement notes[​](#measurement-notes "Direct link to Measurement notes")

* For `consumed.messages`, `error.type={{default}}` is the full batch total, including records whose handlers failed; `error.type=processing_failed` is the overlapping per-record subset. Do not add or subtract the series to infer successful records. The default total and `process.duration` are emitted only when processing/checkpointing completes without an operation error; if that operation returns an error, including a cancellation interruption that returns an error, neither is emitted. A per-record handler failure still emits the `processing_failed` subset and checkpoints that record; retries use the stream retry path, not selective native Kinesis retry.
* `acquire.duration` describes repeated shard-ownership acquisition attempts, not the `Kinsumer` record-runner semaphore. Each observation is the cumulative elapsed time at an unsuccessful acquire check; there is no final sample on successful acquisition or while cancellation is waiting for the next check.
* `wait.duration` is emitted when the next delay is chosen, before the reader waits. A later cancellation does not change that scheduled-value observation. By contrast, `sleep.duration` is emitted only after a per-record delay completes; it is absent when the record is already old enough, the configured delay is zero, or cancellation wins before the timer completes.
* `lag` uses Kinesis' reported `MillisBehindLatest`; it is not a timestamp-derived age of the last record processed.

## CloudWatch stream projections[​](#cloudwatch-stream-projections "Direct link to CloudWatch stream projections")

CloudWatch receives these eight same-name `KindTotal` projections for the reader metrics. Each removes `partition.id` and keeps `stream.name`; the default consumed outcome also omits its default `error.type` dimension.

| Raw metric/outcome                                  | Projection dimensions                           | CloudWatch statistic | Unit                         |
| --------------------------------------------------- | ----------------------------------------------- | -------------------- | ---------------------------- |
| `reads`                                             | `stream.name`                                   | Sum                  | count / UnitCount            |
| `consumed.messages{error.type="{{default}}"}`       | `stream.name` (default error dimension omitted) | Sum                  | count / UnitCount            |
| `consumed.messages{error.type="processing_failed"}` | `stream.name`, `error.type="processing_failed"` | Sum                  | count / UnitCount            |
| `process.duration`                                  | `stream.name`                                   | Average              | ms / UnitMillisecondsAverage |
| `lag`                                               | `stream.name`                                   | Maximum              | ms / UnitMillisecondsMaximum |
| `acquire.duration`                                  | `stream.name`                                   | Maximum              | s / UnitSecondsMaximum       |
| `sleep.duration`                                    | `stream.name`                                   | Average              | ms / UnitMillisecondsAverage |
| `wait.duration`                                     | `stream.name`                                   | Average              | ms / UnitMillisecondsAverage |

These projections do not change the raw stream-and-shard observations or instrument kinds. OpenTelemetry and Prometheus skip `KindTotal` and keep only the raw shard series. Existing raw count defaults for `reads` and the default `consumed.messages` outcome already omit `partition.id` (and the default error dimension), so they seed the stream-level count series; do not add duplicate projection defaults. The `processing_failed` projection has its own stream-level zero default because there is no raw failed default. Histograms, including `lag`, have no zero default; `lag` instead emits an actual initial zero observation and subsequent updates, including 15-second samples while the reader runs.
