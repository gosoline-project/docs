# Gosoline SDK HTTP server package

The Gosoline SDK's `pkg/httpserver` package integrates an HTTP server with the application kernel. Import it as `github.com/justtrackio/gosoline/pkg/httpserver`; `httpserver.New(name, definer)` returns a kernel module factory and reads server configuration from `httpserver.<name>`. The SDK installs its request-metric middleware and server metric recorder as part of constructing the server.

This is distinct from the published `github.com/gosoline-project/httpserver` module documented in the [published HTTP server reference](/docs/pr-5/reference/package-httpserver/.md). The modules are separate implementations, though they currently author the same eight canonical metric names and dimensions.

## Metrics[​](#metrics "Direct link to Metrics")

The SDK installs its metric middleware and recorder by default. After a matched route's middleware chain unwinds, it emits four high-priority monotonic `Count` counters: the statusless `http.server.requests` (`name`) and `http.server.routed.requests` (`name`, `route`, `request.method`), plus `http.server.responses` (`name`, full `response.status_code`, bounded `response.status_class`) and `http.server.routed.responses` (those status dimensions plus `route` and `request.method`). The two request counters count matched requests, and the two response counters count matched responses, including requests aborted by authentication, concurrency, or chaos middleware; unmatched paths emit none. Only the existing request counters receive zero-valued defaults: one per configured server and per registered application route/method pair. The new response counters have no zero defaults. Matched `/health` requests are counted, but its separately registered route has no pre-request zero default. The duration histogram retains the full status code without a class, and the rejection counter remains statusless; neither definition changes. See [Metric schema](/docs/pr-5/reference/metric-schema/.md) for the V1→V2 history and writer-specific selectors.

The SDK installs the metric middleware by default; exporting the observations still requires the application metric daemon. Wire `application.WithMetrics`, set `metric.enabled: true`, and configure at least one writer under `metric.writers`. The table shows canonical Gosoline names and authored units; see [Metric schema](/docs/pr-5/reference/metric-schema/.md) for writer-specific names and duration conversion.

If this SDK server and the published HTTP server both write to the same backend with identical dimension values, the metrics do not carry a source-module dimension that separates the implementations. This SDK metric reference follows Gosoline `v0.68.4-0.20261022095443-a18815d97543`; see the [pinned SDK middleware source](https://github.com/justtrackio/gosoline/blob/a18815d9754336aee9686f5dc45d196d6703f6a8/pkg/httpserver/middleware_metric.go).

For CloudWatch, `http.server.routed.responses` also has a class-projected series with `name`, `route`, `request.method`, and `response.status_class`; the projection omits `response.status_code`. It adds one time series per observed class and name/route/method combination. Prometheus and OpenTelemetry export only the raw five-dimension Counter. For raw Metric Insights selectors and 5xx alarm guidance, see [Metric schema](/docs/pr-5/reference/metric-schema/.md).
